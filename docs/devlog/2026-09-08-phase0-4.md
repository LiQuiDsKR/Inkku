## 한 줄 요약

빈 저장소에서 시작해, 사진을 올려 스티커와 글자와 낙서로 꾸미고 인스타에 공유하기까지
한 바퀴가 실제로 도는 상태가 됐다. 오프라인 캐시와 자동 테스트만 아직 없다.

## 프로젝트 개요

> 첫 기록에만 두는 절이다. 다음 회차부터는 생략한다.

인스타그램 피드에 올릴 사진을 밈 스티커, 손그림 낙서, 꾸밈선, 감성 텍스트로 꾸미는 모바일 웹앱.
사용자는 폰 브라우저에서 사진을 올리고, 스티커와 글자를 손가락으로 배치한 뒤 완성본을 인스타에 공유한다.
팀은 개발 1명, 기획/디자인 1명, 기간 5주.

기술 스택은 착수 시점에 확정했고 바꾸지 않았다.
TypeScript(strict) / React SPA / Vite / Konva + react-konva / Zustand / Tailwind CSS / IndexedDB(idb).
Next.js를 쓰지 않은 이유는 서버가 필요 없기 때문이고, 저장을 localStorage가 아니라 IndexedDB로 잡은 이유는
5MB 제한으로는 사진을 담을 수 없기 때문이다.

## 만든 것

### Phase 0 - 셋업

프로젝트가 아니라 **개발 환경**을 먼저 세운 단계다. 폰에서 확인하는 것이 이 앱의 유일한 진짜 테스트라
거기까지 가는 길을 먼저 뚫었다.

- **빌드와 타입**: Vite + React 18 + TS strict.
  `noUncheckedIndexedAccess`, `noUnusedLocals`, `noFallthroughCasesInSwitch`까지 켰다.
  배열 인덱싱이 `T | undefined`가 되어 손이 더 가지만, 캔버스 코드처럼 인덱스를 자주 다루는 곳에서 사고를 미리 막는다.
- **개발 서버 3종** (`package.json`, `vite.config.ts`)
  - `dev:usb` - 안드로이드 USB 포트 포워딩용. `127.0.0.1`만 바인딩한다
  - `dev:tunnel` - 아이폰용. cloudflared 터널
  - `dev` - `0.0.0.0` 바인딩. 이 PC는 공유기 없이 공인 IP를 직접 받으므로 인터넷에 노출된다
- **디버그 오버레이** (`utils/debugLog.ts`, `components/DebugOverlay.tsx`)
  Windows에서는 아이폰 사파리에 웹 인스펙터를 붙일 수 없다. 실기기에서 에러가 나도 흰 화면 말고는 볼 것이 없어서,
  전역 에러와 제스처 수치를 화면에 직접 띄우는 경로를 따로 만들었다.
  제스처 수치는 매 프레임 바뀌므로 프레임 단위로 합쳐서 통지한다(오버레이가 측정 대상을 방해하면 안 된다).
- **모바일 기본기** (`index.html`, `index.css`)
  viewport에 `user-scalable=no`와 `viewport-fit=cover`, 캔버스 영역 `touch-action: none`,
  안전 영역 패딩 클래스, 문서 스크롤 제거.

### Phase 1 - 캔버스와 사진 레이어

- **데이터 모델** (`layers/types.ts`)
  모든 요소는 레이어다. 위치/크기/회전/투명도/순서는 `BaseLayer`가 공통으로 갖고,
  타입별 필드는 "어떻게 그리는가"만 정의한다.
- **논리 좌표계** (`layers/ratio.ts`)
  레이어 좌표는 화면 픽셀이 아니라 **긴 변 1080 기준 논리 좌표**다.
  편집용(축소)과 내보내기용(고해상도) 캔버스가 같은 좌표를 공유하려면 필수다.
- **저장** (`storage/db.ts`, `imageStore.ts`, `utils/imageResize.ts`)
  IndexedDB v1에 `images`, `projects` 두 스토어. 사진은 긴 변 2160으로 줄이고 EXIF 회전을 반영해 저장한다.
  원본을 그대로 두면 최신 폰의 5000px 사진이 저장 공간을 금방 채우고 iOS 캔버스 메모리 제한에 걸린다.
- **캔버스와 제스처** (`canvas/`)
  Konva 스테이지, 레이어 렌더러, Transformer, 두 손가락 핀치/회전/이동, 휠 조작(PC 확인용), 스테이지 크기 추적.
  주소창이 나타났다 사라지며 높이가 바뀌므로 `ResizeObserver`로 계속 따라간다.
- **화면 3종** (`components/`)
  홈, 비율 선택, 편집. 화면이 셋뿐이고 딥링크도 필요 없어 라우터를 두지 않았다.

### Phase 2 - 스티커, 글자, 히스토리

- **히스토리 30단계** (`store/historyStore.ts`)
  스냅샷에는 레이어 구조만 담고 사진은 `imageId`로만 참조한다.
  모든 레이어 변경이 `projectStore`의 `applyLayers` 한 경로를 지나게 해서, 액션이 늘어도 기록을 빼먹지 않는다.
  결과가 이전과 같으면(맨 위 레이어를 또 맨 위로 보내는 등) 기록도 갱신도 하지 않는다.
- **스티커** (`assets/stickerCatalog.ts`, `canvas/AssetContent.tsx`)
  카테고리 탭 + 그리드. 연달아 탭하면 겹치지 않게 어긋나 놓인다.
  URL 에셋 이미지 캐시를 사진 캐시(IndexedDB)와 같은 구현(`utils/imageLoader.ts`)으로 통일했다.
- **글자** (`fonts/`, `canvas/TextContent.tsx`, `components/TextEditorModal.tsx`)
  웹폰트 4종을 고른 시점에 동적 로드한다. 스타일시트가 붙기를 기다린 뒤 `document.fonts.load`를 부르고,
  도착하면 캔버스를 다시 재고 다시 그린다. 더블탭으로 재편집, 내용을 비우고 완료하면 삭제된다.
- **컨텍스트 바** (`components/LayerContextBar.tsx`)
  순서 4종, 복제, 좌우반전, 삭제, 투명도. 투명도는 드래그당 한 번만 히스토리에 남는다.

### Phase 3 - 배경, 도형, 자유 그리기

- **배경 4종** (`canvas/BackgroundContent.tsx`)
  단색 / 그라데이션 / 무늬 / 사진 흐리게. 그라데이션은 각도를 두 점으로 바꿔 세로로 긴 캔버스에서도 색이 끝까지 나오고,
  무늬는 늘리지 않고 타일로 반복해 비율마다 찌그러지지 않는다.
- **도형 6종** (`canvas/ShapeContent.tsx`)
  전부 원점 중심으로 그려 회전축을 사진/스티커/글자와 통일했다.
  패널에서 색을 고르면 선택된 도형은 즉시 바뀌고, 선택이 없으면 다음에 넣을 도형의 색이 된다.
- **자유 그리기** (`canvas/useBrushDrawing.ts`, `utils/strokeRaster.ts`, `layers/importDrawing.ts`)
  점은 ref에 쌓고 Konva 노드만 직접 갱신한다. 미리보기 획은 별도 레이어에 둬서 사진과 스티커를 다시 그리지 않는다.
  손을 떼면 획을 이미지로 굽고(내보내기 배율에 맞춰 2배 해상도) 일반 레이어로 바꾼다. 획 하나가 레이어 하나.

### Phase 4 - 내보내기, 공유, 자동 저장

- **내보내기** (`export/renderProject.ts`)
  편집 캔버스를 배율만 올려 다시 그린다. Konva가 스테이지 배율을 곱하므로 `pixelRatio = 목표배율 / 스테이지배율`.
  찍기 전에 선택을 풀고 한 프레임 기다린다(Transformer가 결과물에 찍히는 것 방지).
- **공유** (`export/share.ts`)
  `navigator.share({ files })`가 주 경로, 다운로드 링크는 폴백. 공유 시트를 닫은 것(AbortError)은 실패로 보지 않는다.
- **자동 저장** (`store/autoSave.ts`, `storage/projectRepo.ts`)
  프로젝트 스토어를 구독해 800ms 모아서 IndexedDB에 쓴다. 홈의 "이어서 편집"에 레이어 수를 표시한다.

## 겪은 문제

### Phase 0 - 개발 환경

**1. 폰에서 개발 서버에 접속이 안 됨**
`chrome://inspect` 포트 포워딩의 Local address를 `localhost:5173`으로 두면 윈도우가 IPv6 `::1`로 먼저 풀어
연결이 거부된다. 반드시 `127.0.0.1:5173`으로 적는다.

**2. 개발 서버가 인터넷 전체에 노출됨**
이 PC는 공유기 NAT 뒤가 아니라 공인 IP를 직접 받는다. `host: true`로 열면 사내망이 아니라 인터넷에 열린다.
평소에는 `dev:usb`(127.0.0.1 바인딩)를 쓰고, 터널을 쓸 때는 cloudflared가 localhost로 붙으므로 외부 바인딩이 아예 필요 없다.

**3. 터널로 접속하면 "Blocked request. This host is not allowed."**
Vite 6는 모르는 Host 헤더의 요청을 막는다. `allowedHosts`에 터널 도메인을 넣되, 와일드카드 대신
터널 모드에서만 열어 평소에는 차단을 유지했다. HMR도 터널 뒤에서는 443/wss로 붙어야 해서 따로 지정했다.
모드 구분은 환경변수 대신 `--mode tunnel`로 했다. 윈도우 npm 스크립트가 cmd로 실행되면서 `TUNNEL=1 vite` 문법이 깨져
cross-env 같은 의존성을 하나 더 넣어야 하기 때문이다.

**4. 윈도우에서 경로 별칭이 깨짐**
`new URL('./src', import.meta.url).pathname`이 `/D:/...` 형태가 된다. `fileURLToPath`로 감싸야 한다.

**5. 당겨서 새로고침과 바운스가 계속 살아 있음**
`overscroll-behavior`는 `overflow`와 달리 body에서 뷰포트로 전파되지 않는다(CSS 명세의 예외).
반드시 루트(`html`) 요소에 건다.

### Phase 1 - 캔버스

**6. Transformer 핸들이 배율의 제곱만큼 커짐**
`anchorSize`가 화면 픽셀 단위인데 스테이지 축소 배율의 역수를 곱했다. Konva가 자체 보정하므로 값을 그대로 넣어야 한다.

**7. 사진이 보이는데 클릭이 안 됨**
비동기로 도착한 이미지가 씬에는 그려졌는데 히트 그래프가 갱신되지 않았다.
내용이 붙는 시점에 `layer.drawHit()`을 명시적으로 불러야 한다. 클릭이 뒤 배경으로 떨어지면 선택 해제라 포커스까지 풀린다.

**8. 이미지가 영영 로드되지 않음**
`img.decode()`는 문서가 화면에 안 그려지는 상태(백그라운드 탭, 화면 꺼짐)에서 페인트를 기다리며 resolve되지 않는다.
`onload`를 쓴다.

### Phase 2 - 4 - 이번 세션

**9. "이어서 편집"이 흰 화면으로 죽음**
- 증상: 저장된 작업물을 열면 캔버스가 통째로 사라짐
- 원인: 파괴된 Transformer에 `forceUpdate()` 호출. StrictMode가 마운트를 되감을 때 앞선 마운트의 스테이지가 파괴되는데,
  그 노드를 가리키던 상태가 새 ref가 들어오기 전까지 잠깐 남는다. 그 틈에 IndexedDB에서 도착한 이미지가 콜백을 부르면서
  이미 없어진 앵커를 건드렸다
- 조치: `node.getStage()`로 살아 있는지 확인하는 `isLive` 가드를 명령 거는 지점 전부에 추가
- 재발 방지: CLAUDE.md 알려진 함정에 기록

**10. 스티커 패널의 왼쪽 아래 스티커가 안 눌림**
- 원인: 개발용 debug 버튼(`fixed bottom-20 z-50`)이 패널 위에 떠서 탭을 가로챔
- 조치: 디버그 오버레이를 패널보다 낮은 z로 내리고, 패널/컨텍스트 바/툴바에 z를 명시
- 여담: 같은 문제가 뒤에 한 번 더 났다. 컨텍스트 바를 툴바 위로 띄우면서 이번엔 debug 버튼이 가려져 누를 수 없게 됐고,
  버튼을 더 위로 올려 해결했다

**11. 레이어를 고를 때마다 캔버스가 튐**
- 원인: 컨텍스트 바가 흐름에 있어서 나타났다 사라질 때마다 캔버스 영역 높이가 바뀜
- 조치: 컨텍스트 바를 툴바 위에 띄우는 방식으로 변경
- 메모: 자동 확인 스크립트의 좌표가 계속 어긋나면서 발견했다. 손으로만 봤으면
  "맞춰 둔 위치가 왜 자꾸 움직이지" 하고 한참 헤맸을 문제다

**12. 같은 화면에 "뒤로" 버튼 두 개**
상단 바의 뒤로(편집 나가기)와 순서 바꾸기의 뒤로가 겹쳤다. 순서 라벨을 위/아래 표현으로 바꿨다(맨아래 / 아래 / 위 / 맨위).
